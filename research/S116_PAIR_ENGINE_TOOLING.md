## Complete predicates and coverage — CLM-0395 (PROGRAMME_PROVED)

Let p,q be distinct supported primes, n=pq, and 0<=alpha_i<n. A component key is sum M_rc p^(rk+c), where r=0,1,2 and c=0,...,k-1. Unique positional expansion recovers the matrix. A combines each matching column coordinate as a+p((b-a)p^(-1) mod q), reduced modulo n. B works directly with the two residue matrices. CRT ensures both describe exactly the same labelled image; no column permutation is made.

An actual column has order pq iff both prime projections are nonzero: its local orders are respectively 1 or p and 1 or q, and the global order is their least common multiple. Two actual columns coincide iff both corresponding projected columns coincide. A tests gcd(n,three coordinates)=1 and distinct actual columns; B tests both projected nonzero conditions and simultaneous component equality. A repeated column in only one projection is allowed. These tests discard exactly supports outside the registered distinct/full-order class. The generating refinement and covering reductions remain CLM-0384/0385/0391, with the inherited profile-sieve premises of CLM-0378.

**Engine A (`pair_a.py`).** Split the labelled coefficient box into two halves. Enumerate every tuple on each half exactly once. A nonempty bounded zero exists iff a left sum matches the negative of a right sum, except for the empty-empty match. Sort encoded left sums and use lower/upper interval searches for every right sum. All tuples with a fixed sum form an interval. The all-zero tuple is row 0 of each grid; stable sorting places it first among left zero sums. For right row 0 only, advance past that left row if encountered. Thus a different left zero survives, and every nonzero right tuple may still match the empty left tuple. Zeros wholly in either half are retained. A returned tuple is checked against all bounds and all three modular sums.

For the registered profile, the two grid sizes are 4*9*9=324 and 9^3=729, independent of pair values. Every grid sum and matching interval is computed even when a witness exists. Integer arithmetic stays well within int64 for these supported parameters. No probabilistic hashing or floating point enters the predicates.

**Engine B (`pair_b.py`).** Independently decode and row-reduce each component, selecting a different elimination pivot rule. For each free column f, construct the relation vector with free coordinate 1 at f and pivot coordinates minus the reduced column entries. These vectors form a basis for the full kernel: projection to free coordinates is an isomorphism, so every vector occurs exactly once in the enumeration of basis coefficients. In the rank-three, six-column target, the vector counts are 3^3=27 and 5^3=125, including zero.

For every pair of kernel vectors u,v, construct each coefficient x_i in [0,pq-1] by a CRT lookup table built by direct enumeration of residues. Keep exactly x_i<=alpha_i for every i and x nonzero. Since alpha_i<pq, each bounded integer coefficient vector has exactly one residue representative. Hence this test is equivalent to a full bounded zero relation, not merely a pure-component or two-label condition. There are exactly 27*125=3375 vector pairs, with six coordinate comparisons each. Returned witnesses are checked directly in both components. B shares no mathematical helper with A.

The present session checks the exact archive/member and representative-file hashes, sorted uniqueness, lengths, and every key's independent decoder/encoder agreement without joining any target pair. Euclidean division is a bijection between [0,5815950) and [0,145)x[0,40110). The 145 registered shards are exactly [i*40110,(i+1)*40110); they are disjoint and cover the interval. Within each shard, the harness rejects missing, duplicated, reordered or excess ordinals. Shared storage is not an independent mathematical algorithm: the two predicates and traversals, plus independent final record replay, provide the distinct checks.

## Durable execution and independent final audit

The specification pins input byte hashes, all four runtime code hashes, environment, exact profile, every shard and chunk size. The runtime verifies these before running. Each output chunk is written and flushed to a temporary file then replaced atomically; only afterward is its hash-chain commit marker atomically installed. Resume accepts only a contiguous valid committed prefix. An output without a marker is not counted and is recomputed. Corrupt or missing committed data, changed identity, chain gaps, duplicate markers or ordinal faults fail closed. An exception discards all uncommitted decisions of that chunk and commits a terminal FAILED record, not an exclusion. A ZSF record stops at once as an unverified candidate. Budget exhaustion leaves PARTIAL coverage that may be resumed.

Tests inject failure before output, after output and after marker; resumed receipts equal uninterrupted receipts exactly. Zero budget and two-chunk interruption resume correctly. `pair_campaign.audit` independently reads both engine directories, verifies the chain and every ordinal against the registered partition, compares semantic outcomes, reconstructs each actual image by a third direct CRT search, and checks every zero witness.
